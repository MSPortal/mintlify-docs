Dashboards bring configured charts and summary cards together. Company users see the dashboards and data available to their role; MSP staff can use broader views and configure dashboards with the appropriate permissions.

Start with [Read and filter a dashboard](/user-guides/dashboards/read-a-dashboard). Check company scope and each metric’s dates before comparing numbers.

## Dashboard types

| Type | What to expect |
| --- | --- |
| **System** | Built-in layouts such as Ticketing Dashboard and Risk Dashboard. The normal reader does not offer Edit for system dashboards. |
| **Personal** | A dashboard associated with its owner. It is not automatically shared with other users. |
| **Shared** | Available according to active status, sharing, role restrictions and visibility. |
| **Internal only** | Restricted to eligible MSP staff; unavailable to Company users. |
| **External** | A linked or embedded external service, with its own access and viewing behavior. Company-specific setup may be required. |

Widgets also depend on module permissions, integrations and selected-company data. Access to Dashboards alone does not make every widget or record available.

## For MSP staff

Follow [Create and edit a dashboard](/user-guides/dashboards/create-and-edit-dashboard) to create a personal dashboard, add widgets and summary cards, rename it, and save permanent changes. Follow [Manage dashboard settings and access](/user-guides/dashboards/manage-dashboard-settings) for sharing, roles, defaults, sidebar links and dashboard row/bulk actions. For external links, follow [Configure external dashboards](/user-guides/dashboards/configure-external-dashboards) and [Assign company URLs](/user-guides/dashboards/assign-external-dashboard-company-urls). These authoring and settings actions require their applicable permissions.

The reader’s date and width controls only change the current view. They do not save a shared layout. Do not assume only the owner can edit every shared dashboard; authorization depends on the dashboard type and granted permissions. Company user permissions are managed by the MSP.

## External dashboard access

Follow [Open an external dashboard](/user-guides/dashboards/open-external-dashboard) for Company and MSP viewing instructions.

External content may load inside the portal or offer **Open in New Tab** when embedding is blocked or not yet checked. The external service may require its own sign-in. If the expected external dashboard is missing for a company, ask the MSP to check its company-specific link and role access.

## Frequently asked questions

<AccordionGroup>
  <Accordion title="Should Company users start with the dashboard editor?">
    No. Start with Read and filter a dashboard. Ask the MSP for configuration or user-permission changes when needed.
  </Accordion>
  <Accordion title="Are all dashboards ticket dashboards?">
    No. System and custom dashboards can contain different module widgets, including risk information. Ticket summary cards appear only when configured.
  </Accordion>
  <Accordion title="Why does an external dashboard ask me to sign in again?">
    The external service can have its own authentication. Portal dashboard access does not replace that service’s requirements.
  </Accordion>
  <Accordion title="Where does an MSP configure dashboards?">
    Use the custom dashboard editor for permanent layout changes and Settings > Dashboards for configuration, with the applicable permissions. Reader filters do not save a shared layout.
  </Accordion>
</AccordionGroup>
