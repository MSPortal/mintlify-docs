**Audience:** MSP staff responsible for setting up the organization’s portal. Launch Center is not the onboarding task list for a Company user. For client onboarding, use the [client onboarding guides](/user-guides/client-onboarding/index).

Launch Center organizes configuration around your rollout goals. It checks stored configuration and data alongside your progress, so a completed step and a ready client experience are not the same thing.

## Access and prerequisites

Open **Launch Center** from the sidebar, or select **Launch** in the top bar when offered. Availability also depends on your organization’s setup history and whether Launch Center was dismissed.

Reading requires Launch Center read/manage access or the applicable tenant-settings access. Changing the plan requires Launch Center management or tenant-settings management; the primary administrator also has management access. Company users are excluded. Individual embedded setup screens can require their own settings permissions and provider access.

Have the intended rollout goals, responsible staff member and authoritative data sources ready. Connecting integrations, importing users, changing branding and billing are real configuration actions; a launch plan is not a sandbox for those changes.

## Choose a plan

<Steps>
  <Step title="Choose how to start">
    On the welcome screen, select **Build my launch plan** for a guided questionnaire or **Explore first** for an exploration plan. Both start a saved setup workflow. Explore first does not certify the portal as ready for clients.
  </Step>
  <Step title="Choose your focus">
    Select the outcomes you need: client ticketing, self-service, security training, vCIO planning, compliance or a client data foundation. The complete rollout option combines the tracks. Answer the questions about data sources and the pilot or wider rollout.
  </Step>
  <Step title="Build and review">
    Select **Build my plan**. Review the phases and dependencies before changing configuration. **Edit launch plan** lets an authorized manager revisit the goals later; review the resulting steps after saving.
  </Step>
</Steps>

The plan can include Foundation, Connect, Client data, Ticketing, Training, vCIO, Compliance, and Review and launch. Which steps are required depends on the selected goals and systems. Optional work may appear under **Explore later**.

## Complete setup work

1. Select a step in **Setup guide**. Read its purpose, affected areas and verification guidance.
2. Review the embedded setup screen or follow its configuration link. Check the selected integration or company before any save or import.
3. Use that screen's labeled Save, Connect or Import action where offered. Wait for its result. Some controls save immediately; others stage changes.
4. Select **Next** when ready. It runs the step's registered save or continuation flow and can require readiness evidence before marking the step complete.
5. Check the resulting step status and any error before moving on.

**Back** and choosing another step are navigation actions. Do not use them as a guaranteed discard operation: some workspaces save pending changes during navigation. If **Do this later** is offered for an optional step, it can save the current workspace before recording the deferral. It does not undo configuration already saved.

Collapse **Setup guide** to make more room for the workspace, and expand it again to choose another step. Your stored plan can be resumed later, but unsaved text in an embedded form is not guaranteed to survive leaving the page.

## Read readiness findings

Use the readiness summary and **Live verification** to inspect the evidence. Read both the severity and the outcome of each finding.

| Finding | How to respond |
| --- | --- |
| Passing | The checked evidence currently meets that rule. It is not a test of every provider or client action. |
| Blocking | Resolve it before completing the launch. Follow the linked setup step and verify the result. |
| Recommended | Review its effect on the planned rollout even if it does not block completion. |
| Optional | Decide whether the capability belongs in this rollout. |
| Unknown or an evaluation error | Inspect the error and underlying setup. Missing evidence is not a pass. |

Integration and data steps can complete from evidence without a manual checkmark. A later configuration change can make a previously passing check fail. Review the displayed check time and current findings before inviting clients; a progress percentage is not a guarantee that every client workflow works.

**Review the client experience** inspects the selected company and role’s readiness and access information. It does not sign you in as that client or replace testing the actual Company experience.

## Complete or hand off the launch

On **Complete launch**, review all blocking findings. Completion is available only when the required readiness evidence passes. An exploration-only plan must be expanded into a launch plan before it can certify a rollout.

Completing the launch records its completion; it does not itself send client invitations. Readiness monitoring can later report **Needs attention** if required configuration regresses. Resolve the reported cause and recheck the current state.

The **Launch coordinator** identifies the accountable person. Where its selection control is offered, the current coordinator, primary administrator or tenant owner can choose an eligible replacement. Selecting a replacement can save immediately; wait for the result and confirm the displayed coordinator. This transfers launch responsibility, not ownership of the tenant or unrestricted settings access.

## Dismiss Launch Center

An authorized manager can select **Dismiss Launch Center**, review the tenant-wide confirmation, and choose **Remove for everyone**. This hides its sidebar and top-bar entry for the organization. It does not delete the saved setup configuration or undo integrations.

Choose **Cancel** to keep it available. If it was dismissed accidentally and no restore control is offered, contact support rather than repeating setup or disconnecting services.

## Troubleshooting

| Problem | What to do |
| --- | --- |
| Launch Center is missing or redirects | Check role access, prior setup completion and whether it was dismissed. Company users use their own onboarding task list. |
| A plan is visible but cannot be edited | Ask an MSP administrator to review Launch Center management and the embedded screen's permissions. |
| Next reports a save or validation error | Stay on the step, inspect what actually saved, correct the error and retry only the incomplete action. |
| Another person updated the plan | Reopen the current plan and compare the latest values before reapplying your changes. |
| Complete launch is disabled | Resolve blocking or unknown readiness findings and verify the evidence again. |
| A completed step needs attention again | Check the underlying configuration or connection; an earlier pass does not prevent later changes. |

## FAQs

<AccordionGroup>
  <Accordion title="Is Launch Center the client onboarding portal?">
    No. It is an MSP setup workflow for the organization. Client onboarding has separate portals, tasks, forms and access.
  </Accordion>
  <Accordion title="Does Explore first change anything?">
    It starts a saved exploration workflow. It does not complete a full client rollout or make subsequent configuration changes temporary.
  </Accordion>
  <Accordion title="Does Next always mean the setup succeeded?">
    Check the action result and readiness status. A validation, permission, connection or evidence failure can prevent completion.
  </Accordion>
  <Accordion title="Does Do this later discard my edits?">
    No. On supported optional steps it saves the workspace before recording the deferral. Review saved configuration before retrying or moving on.
  </Accordion>
  <Accordion title="Does a readiness pass prove every client can use the feature?">
    No. It proves the specific checked evidence met the rule. Test the actual Company role and workflow before rollout.
  </Accordion>
  <Accordion title="Will completing launch email or invite my clients?">
    Completion records setup readiness. Client invitations and communications are separate actions.
  </Accordion>
  <Accordion title="Does removing Launch Center disconnect my integrations?">
    No. Remove for everyone changes organization-wide navigation visibility and leaves saved configuration in place.
  </Accordion>
  <Accordion title="Can someone with only read access change the plan?">
    No. Plan mutations require management access, and individual setup screens can impose additional permissions.
  </Accordion>
</AccordionGroup>
