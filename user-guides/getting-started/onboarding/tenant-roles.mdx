**Audience:** MSP administrators with role-management access. The current **Settings > Users & Roles > Roles** area manages permission-bearing roles. Launch Center opens this area for its access setup step.

## Configure staff access

1. Review existing access groups and their scope. Use a tenant/staff group for internal MSP users.
2. Create or edit the appropriate group using the access-group controls. Give it a recognizable name and review permissions module by module.
3. Save the group in its editor, then assign it to the intended staff users in **Users**.
4. Check the resulting access using an appropriate staff account. An account-group name alone is not proof of the permissions it contains.

Read, write and management capabilities vary by feature. Review the actual matrix rather than assuming a label such as Technician or Administrator has fixed built-in powers.

## Check launch readiness

Launch Center checks for additional tenant-owned access-group configuration. This is a configuration check, not proof that every staff member has the correct role or that a specific role can open every embedded setup screen. Review assignments and the individual settings permissions as well.

## Recover from access problems

If a tab is missing, ask an authorized administrator to review the relevant users/roles permission. If a saved group change affects existing members, reassess those users' workflows before applying broader changes. Do not create duplicate groups merely to change the launch progress indicator.

## FAQs

<AccordionGroup>
  <Accordion title="Are staff access groups the same as account-team roles?">
    No. Access groups grant permissions. Team Roles organize responsibility and company assignments.
  </Accordion>
  <Accordion title="Does creating an access group assign it to users?">
    No. Review and save user assignments separately.
  </Accordion>
  <Accordion title="Does a launch access check prove every staff permission is correct?">
    No. Test the intended staff role and review its actual permissions.
  </Accordion>
</AccordionGroup>
