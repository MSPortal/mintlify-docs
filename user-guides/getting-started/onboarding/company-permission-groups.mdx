**Audience:** MSP administrators managing client access. Open **Settings > Users & Roles > Roles** and review Company-scoped groups. The old Companies > Permissions instructions no longer describe the primary settings navigation.

## Prepare client access

1. Review the Company-scoped group you intend to use. Check individual permissions, ticket visibility and other available restrictions.
2. Create or edit a group when the existing configuration does not fit. Save in the group editor.
3. Assign the group to the correct people under **Company Users**. Verify company, active status and access group together.
4. Review import defaults and contact-type mappings if a provider imports those users. An explicit mapping can affect existing synchronized users.
5. Check the actual Company experience before inviting a wider audience.

Access groups are permission-bearing roles. **Team Roles** identify assigned staff responsibilities and can affect company scope and the client team display; they are not a substitute for Company access permissions.

## Avoid accidental overexposure

A visible navigation item does not prove the user can read all records behind it. Conversely, hiding a sidebar item is not a security rule. Review the group, company scope and the content's own visibility settings.

Use [change Company-user permissions](/user-guides/settings/change-company-user-permissions) for the assignment workflow. If an imported user's group changes again, review the provider's contact-type rules, company default and integration default instead of repeatedly overriding the same field.

## Verify readiness

A configured access group does not prove that every rollout company has an active, correctly assigned user. Return to Launch Center and inspect both access and client-user findings.
