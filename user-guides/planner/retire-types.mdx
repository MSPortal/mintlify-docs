**Audience:** MSP staff with **Manage** access to Planner Types settings. Company users ask their MSP to review classifications. Deletion also requires active billing and sufficient underlying Planner and Budget access for any reassignment.

<Warning>
If the trash action reports a usage-check failure and no confirmation opens, stop and ask your MSP administrator or support to investigate. No reassignment has started at that stage. The steps below apply when the usage check succeeds and the confirmation opens.
</Warning>

## Review the impact first

A Planner type is a shared definition used across companies. Renaming it through the pencil editor may be more appropriate than deleting it. See [Manage Planner types](/user-guides/planner/manage-types).

Before deleting, check:

- Planner items and budget lines using the type, including archived work.
- Planner templates that select the type.
- Standards category mappings that use it.
- Whether it is the default for new Planner items.

The deletion dialog counts Planner items and budget line items. It does not provide a complete list of every template or Standards mapping. Deleting the type can clear those template and Standards associations; they are not moved by the dialog's replacement choice.

## Delete an unused type

1. Open **Settings > Customization > Types > Planner Types**.
2. Find the exact row and choose its **trash** icon.
3. Read **Delete Planner Type** and confirm the name.
4. Choose **Cancel** to keep it, or **Delete** to remove it.
5. Verify it no longer appears in the catalog.

Opening the confirmation does not delete anything. If usage is detected, the dialog instead asks you to choose a replacement. If deleting the default, explicitly choose the desired replacement default through its star; deletion does not automatically choose one.

## Reassign used work and delete the type

1. Open the type's trash action and review the reported Planner item and budget line counts.
2. Under **Reassign to**, choose a different existing type. The type being deleted is not a replacement option.
3. Check that the target classification makes sense for every affected company.
4. Select **Reassign & Delete**. It remains disabled until you choose a replacement.
5. Wait for the result, then verify the catalog, affected Planner items and relevant budgets.
6. Review Planner templates and Standards mappings separately and choose their intended types where needed.

If no suitable replacement exists, cancel and create the new type first. Cancel before confirmation does not reassign work.

## Budget history and partial failures

Editable **Draft** and **Pending Approval** budget lines can be reassigned. Approved or Obsolete budget baselines keep their recorded snapshots; deletion clears their live type association rather than rewriting that historical classification. Do not expect every historical budget to display the replacement name.

<Warning>
Reassignment and deletion are not one all-or-nothing operation. Some Planner or budget changes can save before a later step fails. If an error occurs, inspect both the old type's usage and the affected records before retrying. An error does not prove nothing changed.
</Warning>

Retiring a type reclassifies or clears associations; it does not delete the Planner work or budget documents themselves. Confirm the final classifications and estimates before treating the task as complete.

## Troubleshooting

| Problem | What to check |
| --- | --- |
| Trash reports a usage-check error and no confirmation opens | Keep the type and report the error to the MSP administrator or support. |
| Trash icon is absent | Planner Types settings Manage permission. |
| Reassign & Delete is disabled | Choose a different existing type under Reassign to. |
| No suitable replacement is listed | Cancel and add the replacement type first. |
| The type reports usage I did not expect | Check archived Planner items and budget lines across companies. |
| Reassignment or deletion fails | Review permissions, billing and the current records; earlier changes may have saved. |
| A template lost its type | Template associations are not part of the dialog's reassignment; review the template separately. |
| A Standards mapping no longer has this type | Choose the appropriate type in that mapping; it is not reassigned by this dialog. |
| An approved budget kept the old name | Its snapshot preserves historical classification. |

## FAQs

<AccordionGroup>
  <Accordion title="Why does the trash action fail without opening a confirmation?">
    The usage check can fail before the dialog opens. No reassignment has started at that stage. Keep the type and ask the MSP administrator or support to investigate; do not treat the action as a successful deletion.
  </Accordion>
  <Accordion title="Where do I delete a Planner type?">
    Use the row's trash icon under Settings > Customization > Types > Planner Types. You need Manage access to these settings.
  </Accordion>
  <Accordion title="Does opening Delete Planner Type immediately remove it?">
    No. Review the name and usage, then confirm Delete or Reassign & Delete. Cancel before confirmation keeps it.
  </Accordion>
  <Accordion title="Why must I choose another type?">
    Planner items or budget lines use the current definition. Choose an appropriate replacement before confirming.
  </Accordion>
  <Accordion title="Can I reassign a type to itself?">
    No. Choose another existing type, or cancel and create the replacement first.
  </Accordion>
  <Accordion title="Does deleting a type delete the underlying Planner items?">
    No. It changes their classification through reassignment. Deleting the work itself is a separate workflow.
  </Accordion>
  <Accordion title="Does the usage warning include Planner templates and Standards mappings?">
    No. It counts Planner items and budget lines. Check templates and Standards mappings separately; deletion can clear their type associations.
  </Accordion>
  <Accordion title="Will the replacement type be applied to every approved budget?">
    No. Locked budget snapshots keep their recorded classification. Editable Draft and Pending Approval lines can be reassigned.
  </Accordion>
  <Accordion title="Does an error mean that no reassignment saved?">
    No. The operation can partly save before a later step fails. Inspect current usage and affected records before retrying.
  </Accordion>
  <Accordion title="Will deleting the default automatically choose another default?">
    No. Explicitly select the intended replacement using its Set as default star.
  </Accordion>
  <Accordion title="Can a Company administrator retire a shared type?">
    No. The MSP manages this shared configuration and its effects across companies.
  </Accordion>
</AccordionGroup>
