Use TimeZest to offer scheduling from ticket templates and display appointments in supported portal views. The setup flow is **Connect → Configure → Status**.

## Before you start

This is an **MSP staff** task requiring integration-management permission and authorized vendor credentials. This provider is available only when enabled for your MSP tenant. If its setup page is unavailable, check availability with your MSPortal administrator. Company users do not configure this connection.

Use a **read/write TimeZest API key** for scheduling. The connection test checks read access by retrieving appointment types and scheduling resources. It does not create a test appointment and therefore does not verify write access.

## Connect the API key

1. Open **Settings > Integrations**, find **TimeZest**, and open setup.
2. Enter the **API Key**, then choose **Test Connection**.
3. Review the returned appointment-type and resource counts. Resolve access errors before continuing.
4. Select **Create Integration** for a new connection. To replace an existing key, test the replacement and select **Update API Key**.

The saved key is masked. A successful read test is not proof that ticket scheduling will succeed with that key.

## Configure features and client access

Choose each capability independently in **Configure**:

| Capability | Result |
| --- | --- |
| **Schedule from ticket templates** | Eligible clients can continue from a supported PSA ticket request to TimeZest scheduling. |
| **Show appointments on calendars** | Eligible clients can see synchronized TimeZest appointments on calendars. |
| **Show appointments on tickets** | Eligible ticket details offer an Appointments tab. |
| **Allow appointment changes** | Eligible users can open the secure TimeZest management link for appointment actions. |

For each enabled capability, choose **Client security roles** and **Company groups** if access should be restricted. Empty lists mean all client roles or all company groups for that dimension. When both restrictions are selected, a client must match **both**. MSP staff retain access to enabled capabilities.

Select **Save All** to persist feature and audience changes. The switches and selections do not save immediately. Feature access still depends on the underlying ticket/calendar permissions and compatible request workflow.

## Configure the ticket template and review status

Enable the relevant scheduling option in the intended ticket template and select an appointment type and schedulable resource offered by TimeZest. A connection alone does not configure every request template. See [Request templates](/user-guides/ticketing/understand-request-templates).

In **Status**, review the currently returned **Appointment types**, **Scheduling resources**, durations and fetched time. Empty lists or a load error need investigation before clients use the template. No specific appointment is booked until the scheduling workflow succeeds.

## Scheduling and changes

A scheduling request, a booked appointment and a changed appointment are separate outcomes. Follow the TimeZest management link to select a time or make an allowed change, then check the resulting appointment state. Creating a PSA ticket does not itself prove an appointment was booked.

Changing an existing appointment can affect real attendees and provider records. This is a scheduling workflow, not a read-only status check.

## Remove the connection

Choose **Delete Integration**, read the confirmation naming TimeZest, and confirm **Delete** only when you intend to remove the saved connection. Cancel leaves it in place. Manage existing appointments in TimeZest; removing a portal connection is not an appointment cancellation workflow.

## Troubleshooting

| Symptom | What to check |
| --- | --- |
| Read test passes but scheduling fails | The key must also allow writes; setup deliberately does not test a real scheduling request. |
| Client cannot see scheduling | Feature enabled, saved role and company-group restrictions, template configuration and underlying permissions. |
| Appointment type is missing | Current TimeZest types/resources and the Status fetch result. |
| Calendar or ticket appointment is absent | Correct company/ticket, enabled display capability, sync freshness and an actually booked appointment. |
| Configuration did not persist | Select **Save All** on Configure; key replacement uses **Update API Key** separately. |

    No. The client must complete the subsequent TimeZest scheduling flow.
