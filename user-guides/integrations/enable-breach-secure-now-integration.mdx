Use Breach Secure Now (BSN) to bring client and user awareness metrics into MSPortal. Setup is for **MSP staff with integration management permission**. Mapping assigns provider records to MSPortal companies; it does not invite users or change their portal roles.

## Prepare the connection

In your Breach Secure Now partner portal, locate the MSPortal integration and obtain its **Partner integration key**. If MSPortal or the key is unavailable, ask BSN to check the partner's integration access. MSPortal resolves the partner from that key; no separate Partner ID is entered.

Open **Settings > Integrations**, find **Breach Secure Now** under **Add integration**, and connect it. Open **Configure** on an existing connection when maintaining that account.

## Connect

<Steps>
  <Step title="Enter the key and endpoint">
    Enter **Partner integration key**. Keep **API base URL** at the prefilled `https://api.pii-protect.com/securedapiaccess` unless you have verified different connection instructions.
  </Step>
  <Step title="Test the account">
    Select **Test Connection** and review the returned partner or sample-client information. A test may show a sample count; do not use it as proof that the complete client inventory has synchronized.
  </Step>
  <Step title="Save the connection">
    Select **Connect**, wait for success, then **Next**. This saves the connection and requests client discovery in the background. For a saved connection, **Save connection** persists credential changes; testing alone does not.
  </Step>
</Steps>

## Map companies

On **Map companies**, wait for discovered BSN clients. If the list is empty, use **Sync Clients**, then revisit the list after discovery completes. Review **Quick Match** proposals or select a company manually.

Pending links require **Import Selected**, or **Next** to save pending choices. Saving BSN mappings also requests user-data synchronization. Check for a successful save before leaving; a queued sync is not completed user coverage.

<Warning>
**Create new company** saves the MSPortal company before its pending mapping is applied. Removing a saved mapping is immediate. Closing the wizard does not undo either operation.
</Warning>

## Review Status

| Statistic | What to check |
| --- | --- |
| **Linked clients** | Mapped clients compared with discovered clients. |
| **Active users** | Active users compared with synchronized users. |
| **Avg. employee secure score** | Available BSN score information. |
| **Training completion** | Available training completion information. |
| **Users with breaches** / **Total user breaches** | Reported exposure in the available synchronized data. |

Use **Sync clients** for discovery, **Sync users** for mapped user data, or **Sync all** for the combined workflow. These request background work. The page checks again shortly after starting a sync, but a long run may need you to revisit Status later.

Missing values shown as **Not synced**, zero counts and a setup-active message do not establish that everyone is trained or free of breach exposure. Check the mapped scope and freshness, then inspect the relevant Security Awareness or reporting view. **Complete Setup** returns to Integrations without waiting for completion.

## Update or remove the connection

On an existing connection, the saved key can be retested without re-entering it. To rotate it, enter the replacement and select **Save connection**. Check discovery afterward; a credential-save success does not establish that new client records arrived.

**Delete** opens a confirmation for removing this connection, its synchronized BSN data and stored credentials. Correct a mapping or update a key without deleting the entire connection.

## Troubleshooting

| Symptom | What to check |
| --- | --- |
| Key not recognized | Copy the complete Partner integration key from the intended partner's MSPortal integration. Confirm that integration is enabled in BSN. |
| Setup reports a service configuration problem | Ask MSPortal support to investigate the reported error; a new Partner ID is not required. |
| No clients | Verify the saved connection and run client discovery before mapping. |
| No user metrics | Save company mappings, request user sync and inspect its outcome. |
| Counts still look old | Revisit Status after the background work; the initial success message only confirms the request. |

## Frequently asked questions

<AccordionGroup>
  <Accordion title="Do I need a Partner ID for Breach Secure Now?">
    No. Enter the **Partner integration key** from the BSN MSPortal integration; MSPortal resolves the partner account from it.
  </Accordion>
  <Accordion title="Does the BSN test count prove that every client was imported?">
    No. The connection test can report sample-client information. Review the discovered client list and saved mappings for actual coverage.
  </Accordion>
  <Accordion title="Does Test Connection rotate the stored BSN key?">
    No. After entering the replacement, use **Save connection**. A test only checks credentials.
  </Accordion>
  <Accordion title="When are pending BSN mappings saved?">
    Use **Import Selected**, or **Next** to save pending mappings. A created company already exists before its pending link is saved.
  </Accordion>
  <Accordion title="What is the difference between Sync clients and Sync users?">
    **Sync clients** discovers the mapping inventory; **Sync users** requests training and user data for mapped clients. **Sync all** runs the combined workflow.
  </Accordion>
  <Accordion title="Does zero BSN breach exposure mean a client is safe?">
    A zero only describes available synchronized data. Check company mapping, freshness and provider coverage before drawing conclusions.
  </Accordion>
  <Accordion title="Does Complete Setup wait for BSN synchronization?">
    No. Check Status and actual reporting data after the background work completes.
  </Accordion>
  <Accordion title="Can Company users connect their own BSN account?">
    The wizard requires MSP integration management access. Mapping provider users does not invite them or grant portal roles.
  </Accordion>
</AccordionGroup>
