Connect Cork to bring its compliance events, endpoints, inboxes and vulnerabilities into MSPortal. Setup belongs to **MSP staff with Integrations settings and management access**. Company users see only the security information their permissions and company scope allow.

## Connect Cork

1. Obtain the API key for the Cork account you intend to connect. Keep it out of shared documents and screenshots.
2. Open **Settings > Integrations**, find **Cork**, and open setup.
3. On **Connect**, enter the **API Key** and choose **Test Connection**.
4. After a successful test, choose **Create Integration**. Testing alone does not create the connection.
5. After creation succeeds, choose **Next** for **Map**. Creation requests a client sync in the background; saving the connection does not establish that clients have finished importing.

## Map clients

Wait for Cork clients to load. Use the mapping view’s sync action if clients have not appeared, then allow time for the background result.

Choose an existing MSPortal company for a Cork client, or use **Quick Match** and review the selected suggestions. Manual matches and applied suggestions remain pending until **Import Selected** or the wizard’s **Next** applies them.

Cork mapping also supports creating companies. Search existing companies first to avoid duplicates. A per-row company creation saves the new company immediately; its Cork link still needs to be applied. Bulk import can create companies for selected unlinked clients as well as save pending links. Review all selected and pending changes before importing; table filters do not discard pending work.

Removing a saved company link is immediate. Clearing an unsaved suggestion only removes that pending choice. After applying links, review the saved company names before proceeding. Leaving Map with **Next** requests downstream security synchronization for the mapped clients.

For the shared controls and partial-result checks, see [Company Mapping](/user-guides/settings/integration-company-mapping).

## Review Import

The final **Import** step shows counts for **Compliance Events**, **Endpoints**, **Inboxes** and **Vulnerabilities**, with last-sync information when available. These are connection-level indicators; a nonzero count does not prove every mapped client or data feed is current.

**Sync All Data** resets sync tracking and requests background imports for the four security datasets. It is an operational action, not a page refresh. Use the Map step’s client sync to update the client list. Allow time for results and check the affected data views; the sync-start message does not prove completion.

**Complete Setup** attempts to apply any registered pending mapping changes and exits setup. It does not wait for every security import to complete, and is not evidence of a clean security assessment.

## Existing connections and credentials

Reopen setup to review mapping and import status. On Connect, the existing **Connection Verified** state can reflect the saved connection; it is not a new provider test.

**Retest Connection** checks the saved key when the field is blank or masked, or checks a replacement you enter. This Cork wizard does not provide a credential-update save action. Do not assume that entering and successfully testing a new key rotates the saved credential. Contact support for a supported rotation path before revoking the key in use.

**Delete** opens a confirmation for removing the MSPortal integration. Review dependent security data and mappings before confirming. This is separate from closing your Cork account or resolving security findings in Cork.

## Use the imported information

Open [Security](/user-guides/security/index) for the available reader views. Cork supplies [compliance events](/user-guides/security/read-cork-events), [vulnerabilities](/user-guides/security/read-vulnerabilities) and endpoint information. This is distinct from configuring MSPortal’s Compliance assessments and check schedules.

## Troubleshooting

- **Connection test fails:** check the intended Cork account and API key. A passed test does not prove all later dataset requests will succeed.
- **Client missing:** inspect the client sync result before creating a duplicate portal company.
- **Company has no findings:** verify its saved mapping and dataset freshness. Empty results do not prove the company is secure.
- **Sync started but counts are unchanged:** allow time for background processing and inspect the eventual outcome. Avoid repeatedly restarting a full sync.
- **Newly typed key works but imports still fail:** retesting is not credential rotation in this wizard.

## Frequently asked questions

<AccordionGroup>
  <Accordion title="Does Test Connection create Cork?">
    No. After testing succeeds, choose Create Integration, then Next to map clients.
  </Accordion>
  <Accordion title="When do Cork company mappings save?">
    Import Selected or Next applies pending mappings. Saved-link removal is immediate; per-row company creation saves the company before its pending link is applied.
  </Accordion>
  <Accordion title="Does Quick Match guarantee the correct company?">
    No. Review its suggestions and the full pending selection before applying changes.
  </Accordion>
  <Accordion title="Does Sync All Data refresh the page only?">
    No. It resets sync tracking and requests background imports for compliance events, endpoints, inboxes and vulnerabilities.
  </Accordion>
  <Accordion title="Does Complete Setup mean all security data finished syncing?">
    No. Check the resulting datasets and freshness separately.
  </Accordion>
  <Accordion title="Can I rotate the Cork key by retesting a replacement?">
    No. The current wizard tests the entered key but provides no credential-update save action. Use a supported rotation path before revoking the saved key.
  </Accordion>
  <Accordion title="Do zero Cork findings prove a company is secure?">
    No. Check company mapping, access, provider coverage and successful data synchronization first.
  </Accordion>
</AccordionGroup>
