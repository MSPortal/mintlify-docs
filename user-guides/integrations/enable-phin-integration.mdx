Connect Phin Security to review synchronized training status, campaign information and report artifacts alongside your client data. This is an **MSP setup task** requiring integration management permission. Company users use the training and reporting views their IT provider makes available.

## Before you start

Have your Phin **Partner ID**, **Client ID** and **Client Secret**, plus the MSPortal companies you intend to map. In Phin, enable **Phin API** from the partner-level integration page. Keep the secret when it is first displayed; rotating it requires updating other connections that use it. See [Phin API setup](https://www.phinsecurity.com/knowledge/phin-api-quick-start-guide) and [finding your Partner ID](https://www.phinsecurity.com/knowledge/find-your-phin-partner-id).

## Connect and choose data

<Steps>
  <Step title="Open the intended connection">
    Open **Settings > Integrations**, find **Phin Security**, and connect it. To change a saved connection, open **Configure** on that connection; do not start another connection accidentally.
  </Step>
  <Step title="Test, then save">
    On **Connect**, enter all three credential fields and select **Test Connection**. Review the partner returned by the test. Select **Connect Phin** to save, then **Next**. A successful test alone does not create the connection.
  </Step>
  <Step title="Save the synchronization choices">
    On **Configure**, choose the datasets below and select **Save Sync Settings** before **Next**. Switching a toggle only changes the draft until this save succeeds.
  </Step>
</Steps>

| Option | Purpose |
| --- | --- |
| **Companies** | Discover Phin companies for mapping. |
| **Training Status** | User training status and phishing aggregates. |
| **Active Campaigns** | Campaign metadata for mapped companies. |
| **Report Artifacts** | Metadata for available Phin report PDFs. This count does not prove a report is downloadable. |

## Map companies and review status

On **Map Companies**, review each Phin company and choose its MSPortal company. **Quick Match** proposes name matches; check the selections before applying them. Use **Import Selected** to persist pending links, or **Next** to save pending choices and request the follow-on data sync.

<Warning>
Creating a company saves the new MSPortal company immediately, then stages its link. Save the pending link too. Removing an existing mapping takes effect immediately; leaving the wizard does not undo it.
</Warning>

On **Status**, review Companies, Training users, Active campaigns, Report artifacts and the available Last synced time. Follow **Security Training** or **Security Awareness** to inspect the actual data. **Complete Setup** exits the wizard; it does not wait for all background work. Reopen the status step after a sync if counts have not changed.

## Maintain the connection

Open the saved connection and use **Save Connection** after changing credentials. The masked secret represents the stored value. The separate **Test Connection** button needs the actual secret entered again; an existing verified message is not a fresh test. Changing credentials does not itself prove the new company inventory has arrived: review the mapping list and use its sync control when needed.

Use the connection's **Delete** action only when you intend to remove that connection and its synchronized Phin data and stored credentials. Confirm the dialog carefully. This is not the way to rotate a secret or correct one company mapping.

## Troubleshooting

| Symptom | What to check |
| --- | --- |
| Test is disabled on an existing connection | Enter the actual client secret to run a fresh test. Keep credentials out of support screenshots. |
| No companies appear | Correct partner credentials, saved connection, Companies sync enabled, and completed discovery. |
| Company has no training or campaigns | Saved mapping, the relevant sync switch, provider data availability and last successful sync. |
| Settings reverted after leaving | Use **Save Sync Settings**; the step heading and Next do not replace that save. |
| Status says complete but counts are missing | Completion is navigation. Inspect actual records and sync results before relying on coverage. |

## Frequently asked questions

<AccordionGroup>
  <Accordion title="Does Test Connection save my Phin credentials?">
    No. Use **Connect Phin** for a new connection or **Save Connection** for an existing one. Then move to the next step.
  </Accordion>
  <Accordion title="Do Phin sync switches save immediately?">
    No. Select **Save Sync Settings** on Configure before leaving the step.
  </Accordion>
  <Accordion title="Why is Test Connection disabled with a masked Phin secret?">
    A fresh test needs the actual client secret. The masked value represents a stored secret and is not sent as a usable test credential.
  </Accordion>
  <Accordion title="Does creating a company finish its Phin mapping?">
    The company is created immediately, but its link is pending until you save it with **Import Selected** or **Next**.
  </Accordion>
  <Accordion title="Can I undo an unlink by closing the Phin wizard?">
    No. Removing an existing mapping saves immediately. Select and save the correct company again if you need to restore the link.
  </Accordion>
  <Accordion title="Does a Phin report-artifact count prove that I can download a PDF?">
    No. It counts synchronized report metadata. Open the relevant reporting view and check the available report and access.
  </Accordion>
  <Accordion title="Does Complete Setup mean every Phin dataset has finished syncing?">
    No. Background sync can continue. Check mapping, dataset switches, timestamps and the actual training or reporting view.
  </Accordion>
  <Accordion title="Can a Company user configure Phin?">
    This setup is for MSP staff with integration management permission. Company users access only the training and reporting views their IT provider enables.
  </Accordion>
</AccordionGroup>
