Connect **Spanning Backup** to report Microsoft 365 backup inventory and health. The wizard uses **Connect → Configure Sync → Map Tenants → Status**.

## Before you start

This is an **MSP staff** task requiring integration-management permission and authorized vendor credentials. This provider is available only when enabled for your MSP tenant. If its setup page is unavailable, check availability with your MSPortal administrator. Company users do not configure this connection.

Use a **UniView Client ID** and **UniView Client Secret** with access to your Spanning Microsoft 365 tenants. Obtain these from UniView API Access. One connection can discover multiple accessible tenants; it is not a one-credential-per-client form.

## Connect and save credentials

1. Open **Settings > Integrations**, find **Spanning Backup**, and open its setup action. For an established connection, choose **Configure** on that connection.
2. Enter the credential pair and select **Test Connection**.
3. Review the result. A successful API response can still return no accessible tenants; confirm the account has the intended scope.
4. Select **Create Integration** to save a new connection. On an existing connection, use **Save credentials** after testing changed values.

The test and save are separate. Changing a field invalidates the prior test result. An existing saved connection indicator does not mean a new live test just ran.

## Choose the data to synchronize

**Microsoft 365 tenants** are always discovered. Choose **Protected user inventory** and **Backup health and history**, then select **Save sync settings**. The user inventory includes standard and archived users returned by UniView.

Creating a connection, saving replacement credentials or saving sync settings can request background synchronization. Check its result rather than treating the save as proof that all data is ready.

Changing the switches is a draft until **Save sync settings** succeeds. Save this step before navigating onward; the mapping save is a separate operation.

## Map tenants to companies

1. Open **Map Tenants** and review the discovered names and domains.
2. Choose the existing MSPortal company for each intended row. **Quick Match** provides suggestions to review; it does not establish that the company is correct.
3. Check both selected imports and pending links, then use **Import Selected** to apply them. The wizard also attempts to save pending mappings before leaving the mapping step.
4. Verify the saved company association before relying on company-scoped reporting.

Removing a saved link takes effect immediately. Creating a company on the mapping screen creates it immediately, while its link is pending until saved. Reuse existing companies where appropriate. Leaving the mapping step can start a detailed background sync.

## Read status and backup health

In **Status**, review mapped tenants, protected seats or users, services backed up, workload summaries and the last-sync value. If **Backup data is still preparing** appears, check the mapping and first detailed sync before interpreting missing data as healthy.

Use **View backup health** to continue to the Backup module, or **Manage mappings** to return to company mapping. **Complete Setup** exits the wizard; it is not a guarantee that all workloads have finished synchronizing.

Backup health records the rolling seven-day workload status supplied by UniView for Exchange, OneDrive, SharePoint and Teams. A captured trend is not a guarantee of complete historical restore-point coverage. Use Spanning for restore operations and provider-level investigation.

## Maintain or disconnect

Reopen the specific connection to review status or replace credentials. Test the changed values and use **Save credentials**. Do not regenerate vendor credentials simply to retry a page load.

To remove the connection, use its delete/disconnect control, read the named confirmation and proceed only when you intend to remove the stored connection and associated synchronized data. Removing MSPortal’s connection does not revoke the vendor credential itself.

## Troubleshooting

| Symptom | What to check |
| --- | --- |
| Connection test fails | Correct provider credential type, matching pair, vendor access and reported error. |
| No tenants appear | The credential’s accessible customer scope and discovery result. |
| Backup data is still preparing | Saved company links, enabled datasets, first detailed sync and any recorded error. |
| A workload is missing | Provider support, enabled data options and current source coverage. |
| A change did not persist | Use Save credentials or Save sync settings for the corresponding form; mapping has its own submission. |
