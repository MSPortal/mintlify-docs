Connect CyberHoot to review customer awareness metrics, user compliance, HootScore and available HootPhish results. This is an **MSP integration management** workflow. Availability is tenant-dependent; ask your MSPortal administrator or support if CyberHoot is not offered in **Settings > Integrations**.

## Before you start

Obtain the **API URL** and **API key** from your CyberHoot Partner portal. Use the supplied HTTPS URL ending in `/api`, such as `https://autopilot.cyberhoot.com/api`; do not use a portal login page. Available metrics depend on the customer's CyberHoot capabilities and Power-Ups. A missing capability is not a zero score.

## Connect and map

<Steps>
  <Step title="Open CyberHoot setup">
    Find CyberHoot in **Settings > Integrations**. Connect a new account, or open **Configure** on the intended saved connection.
  </Step>
  <Step title="Test, then Connect">
    Enter **API URL** and **API key**, select **Test Connection**, and review the returned partner and customer information. Select **Connect** to persist the new connection, then **Next**. Saving begins customer discovery; a test alone does not save.
  </Step>
  <Step title="Review customer matches">
    On **Map companies**, review customer names and any supplied Domain. Use **Quick Match** to propose matches or select an MSPortal company manually. A domain helps identify the customer but is not proof that a suggested match is correct.
  </Step>
  <Step title="Save pending mappings">
    Select **Import Selected**, or use **Next** to save pending links. Saving requests a detailed sync for the affected customers. Map at least one customer before expecting customer-level reporting data.
  </Step>
</Steps>

<Warning>
Creating a company persists the MSPortal company first and stages its mapping separately. Removing an existing customer mapping is immediate. Neither is undone by closing setup.
</Warning>

## Inspect Status

Review **Mapped customers**, **Active users**, **Mean HootScore**, **HootPhish challenges** and any **Last synced** time. **Not provided** means no applicable value is available; do not interpret it as a perfect score or absence of phishing activity.

Use **View security awareness** or **View reports** to inspect available data. **Complete Setup** exits the wizard. It does not wait for customer discovery, user data or challenge results to finish. Revisit Status after the background work; the current page is not a continuously updating progress monitor.

## Maintain the connection

For credential changes, reopen the intended connection, edit the fields, run **Test Connection**, then select **Save connection**. The saved-key mask can be used for a retest; testing a new key does not store it. Saving a connection requests fresh customer discovery. Review mappings afterward, especially if the API account changed.

Mapped customers are synchronized on the configured recurring schedule. Do not repeatedly save credentials or remap customers just to force a refresh. If records remain stale, check the account capabilities, mapping and reported sync outcome, and ask support to investigate.

The wizard's **Delete** confirmation removes the connection, its synchronized CyberHoot data and stored credentials. Use it only when intentionally disconnecting that account.

## Troubleshooting

| Symptom | What to check |
| --- | --- |
| CyberHoot is unavailable | Tenant availability and MSP integration management access. |
| Connection fails | Correct HTTPS API URL ending in `/api`, current key, and enabled partner access. |
| No customers to map | Saved connection and completed discovery. Testing alone does not populate the saved setup. |
| Customers exist but metrics are missing | Saved company mappings, customer capabilities and completed detailed sync. |
| HootScore is Not provided | The available source data does not supply a score; it is not a zero or pass. |

## Frequently asked questions

<AccordionGroup>
  <Accordion title="Can every tenant configure CyberHoot?">
    Availability is tenant-dependent, and setup requires MSP integration management permission. Ask your administrator or support if the card is absent.
  </Accordion>
  <Accordion title="Does testing CyberHoot save the API key?">
    No. Use **Connect** for a new connection or **Save connection** for a saved one.
  </Accordion>
  <Accordion title="Does CyberHoot Quick Match guarantee the right company?">
    No. Review proposed names and any supplied Domain, then save the intended links with **Import Selected** or **Next**.
  </Accordion>
  <Accordion title="Does creating a company automatically persist its CyberHoot link?">
    It creates the MSPortal company immediately and stages the link. Save the pending mapping separately.
  </Accordion>
  <Accordion title="Does Not provided mean a CyberHoot customer has no phishing issues?">
    No. It indicates missing applicable data or capability. Check the customer Power-Ups, mapping and sync outcome.
  </Accordion>
  <Accordion title="Does Complete Setup finish the CyberHoot import?">
    No. Background work can continue. Revisit Status and inspect the actual awareness or reporting view.
  </Accordion>
  <Accordion title="Should I keep resaving CyberHoot credentials to refresh scores?">
    No. Use the configured recurring sync and investigate persistent stale data, mapping and capability issues. Save connection when maintaining the connection.
  </Accordion>
  <Accordion title="Can Company users manage CyberHoot mappings?">
    The wizard is an MSP integration management task. Company users see only the data and views made available through their portal access.
  </Accordion>
</AccordionGroup>
