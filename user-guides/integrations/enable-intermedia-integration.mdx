Intermedia setup currently provides a **credential pilot** for Unite Extend Analytics. It verifies and stores a service account for integration work. A connected status does not establish that call history, usage dashboards or automatic analytics synchronization are available.

## Before you start

This is an **MSP staff** task requiring integration-management permission and authorized vendor credentials. This provider is available only when enabled for your MSP tenant. If its setup page is unavailable, check availability with your MSPortal administrator. Company users do not configure this connection.

Obtain a **Client ID** and **Secret key** for an Intermedia Unite Extend service account with Analytics API access. The setup page identifies the HostPilot Unite Extend API access area; have your Intermedia administrator confirm the appropriate service account and access.

## Test and connect

1. Open **Settings > Integrations**, find **Intermedia**, and open the setup page.
2. Enter **Client ID** and **Secret key** in the service-account form.
3. Select **Test Connection**. A successful result means Intermedia issued an Analytics API token for that account.
4. Select **Connect** to save the connection. Saving the credential intake also notifies the MSPortal team that the account has been connected for integration work.

## Update an existing connection

Open **Configure** for the correct Intermedia connection. Stored values are masked. Enter the replacement values, test them, then choose **Save Changes**. Editing a field invalidates the prior test state. A successful retest alone does not persist the replacement; saved connection text on entry is not a new test.

Changed credential submissions can also notify the MSPortal team. Do not submit a replacement merely to explore the form.

## Disconnect

Choose **Disconnect**, read the **Disconnect Intermedia?** confirmation, and confirm only if you intend to remove the connection and its stored credentials. Cancel leaves it in place. This does not revoke the Intermedia service account itself.

## Troubleshooting

| Symptom | What to check |
| --- | --- |
| Pilot not visible | Tenant availability and integration permissions. |
| Test fails | Correct Client ID/Secret key pair and Analytics API access. |
| Save disabled | Required fields, a successful test of the current values and management permission. |
| Connected but no call reports | The current pilot verifies credentials; it does not promise a completed analytics sync or dashboard. |

## Frequently asked questions

<AccordionGroup>
  <Accordion title="Does Connected mean call reporting is ready?">
    No. The current pilot verifies and stores the service-account credentials. It does not prove analytics records are being synchronized.
  </Accordion>
  <Accordion title="What does Test Connection verify?">
    That Intermedia can issue an Analytics API access token for the service account. It does not load and verify a complete call-reporting dataset.
  </Accordion>
  <Accordion title="Does submitting credentials have another effect?">
    Yes. Credential intake notifies the MSPortal team so integration work can proceed. Changed credential submissions can notify them too.
  </Accordion>
  <Accordion title="Can I update credentials by retesting?">
    No. Test the changed values and choose **Save Changes**.
  </Accordion>
  <Accordion title="Does Disconnect delete the vendor account?">
    No. It removes the MSPortal connection and stored credentials; vendor account administration is separate.
  </Accordion>
</AccordionGroup>
