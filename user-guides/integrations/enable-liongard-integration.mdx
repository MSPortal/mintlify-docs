Connect Liongard from **Settings > Integrations > Liongard > Configure**. The setup page has **Connect**, **Map**, and **Configure** steps. It imports Liongard data for MSP workflows; connecting alone does not share documentation with clients or prove a compliance check has passed.

## Before you start

Use an MSP staff account with permission to manage integrations and access to the relevant companies. Have your Liongard instance address, **Access Key ID**, and **Access Key Secret** ready. Company portal users do not configure this integration.

Liongard's documented credential path is your profile menu > **Account Settings > Access Tokens > Generate New Token**. Copy the ID and secret securely; the secret is not shown after you leave that page. Use a user with the API permissions needed for this integration. See [Liongard's authentication instructions](https://docs.liongard.com/reference/authentication) for the current vendor procedure. Choose the token lifetime under your organization's credential policy.

## Connect and save a new integration

<Steps>
  <Step title="Enter the connection details">
    In **Connect**, enter the actual instance name from your Liongard address or its full `https://<instance>.app.liongard.com` URL. Enter the **Access Key ID** and **Access Key Secret** from the same token.
  </Step>
  <Step title="Test Connection">
    Click **Test Connection**. A successful test confirms the supplied credentials can access the tested Liongard endpoint. It does not save the integration or verify every data feed.
  </Step>
  <Step title="Create Integration">
    After the test succeeds, click **Create Integration**. This saves the connection and starts initial environment discovery. Allow the background work to finish before expecting all environments or metrics.
  </Step>
</Steps>

For an existing connection, a verified indicator can reflect its saved setup state. Run a fresh test when you need current credential evidence. The current wizard's test action does **not** save replacement credentials, even where the field hint says **Enter to update**. Do not assume a successful retest rotates the stored key. Coordinate credential replacement with your portal administrator or MSPortal support before revoking the working key.

## Map environments to companies

Open **Map** and match each Liongard environment to the correct MSPortal company. Review proposed name matches before saving; similar names do not establish that two records represent the same client.

- Use existing companies where possible. Follow [company mapping](/user-guides/settings/integration-company-mapping) for the shared matching controls.
- A newly created company is saved when you create it; cancelling a later mapping does not remove that company.
- Pending matches need the mapping save action. Use **Next** to save pending mappings when advancing through the wizard; clicking a step heading is not a substitute for that save.
- Removing an existing mapping clears the saved environment-to-company link immediately. It is not a draft undo and does not delete the Liongard environment or the MSPortal company.

Verify the company on the resulting imported records. An environment link does not establish device matching, documentation sharing, or a successful compliance evaluation.

## Review Configure and sync

**Configure** shows **Synced Data** counts for environments, inspectors, systems, metrics, metric values, and detections, together with the available last-sync information. This screen does not contain separate switches to enable each data category.

Use **Sync All Data** when you intend to request fresh data from Liongard. This starts background work; a success message or a short refresh of the counters is not proof that every sync stage completed. Check current counts, timestamps, mapped companies, and the records you intend to use. If zero counts persist, check mapping and connection access rather than repeatedly starting more jobs.

**Complete Setup** finishes the wizard and returns to integrations. It does not wait for all imported data to finish processing.

## Use the imported data

Open **Settings > Compliance > Metrics** to review evaluations and create metric-linked checks. Use **Settings > Documentation > Liongard** to configure inspector or system sharing separately. Review device matching before relying on per-device compliance results.

Deleting the integration is a separate confirmed action. Do not use deletion as a routine way to refresh data or repair a failed test; first establish the connection or mapping problem and the impact of removing the integration.

## Frequently asked questions

<AccordionGroup>
  <Accordion title="Does Test Connection save my new integration?">
    No. Test Connection checks the supplied credentials. Use Create Integration to save a new connection, then verify background discovery and mapped data separately.
  </Accordion>
  <Accordion title="Does retesting an existing connection rotate its saved keys?">
    No. The current test action does not persist replacement keys. Coordinate an actual credential replacement before revoking the working token; a green test result is not a saved rotation.
  </Accordion>
  <Accordion title="Do I need to create every company before opening the wizard?">
    You can map existing companies or create a company through the mapping workflow. Creation saves the company before the environment mapping is saved, so cancelling a match does not delete the company.
  </Accordion>
  <Accordion title="Can I undo an unlink by leaving the wizard?">
    No. Removing a saved environment mapping clears that link immediately. Re-map the environment deliberately if the removal was unintended.
  </Accordion>
  <Accordion title="Where are the separate metric and detection sync switches?">
    Configure shows Synced Data counters and Sync All Data. The current wizard does not expose a separate enable switch for each data category.
  </Accordion>
  <Accordion title="Does Complete Setup mean all Liongard data is ready?">
    No. It completes the setup flow, while sync work can continue in the background. Verify relevant records, company mappings and timestamps before using them.
  </Accordion>
  <Accordion title="Will connecting Liongard expose its data to my clients?">
    Connection and import do not create client documentation sharing rules. Configure Liongard documentation visibility separately and verify access with the intended Company user.
  </Accordion>
</AccordionGroup>
