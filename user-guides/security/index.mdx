**Audience:** Company users and MSP staff. Your MSP manages permissions, provider connections, and company mapping.

Open **Security** from the sidebar, then confirm your company selection. The available tabs depend on active integrations and permissions. A missing tab or **Security integration unavailable** message does not mean that the company has no security issues.

## Find the right section

| Section | Source and purpose |
| --- | --- |
| **Dashboard** | Summaries from available Cork, Acronis, and Huntress integrations. |
| **Compliance** | Cork security compliance events, affected entities, and event evidence. |
| **Vulnerabilities** | Cork software findings, CVE links, CVSS, and priority. |
| **Endpoints** | Cork and Acronis endpoint information. |
| **EDR Incidents** | Acronis endpoint detection and response incidents. |
| **Security Awareness** | Available awareness data from Breach Secure Now, Phin, Huntress, and CyberHoot. |
| **Huntress** | Huntress security items and summaries. |

Security read access is required for the security-report tabs. **Security Awareness** has its own read permission and can be available independently. Company admins should ask their MSP to change access; they do not manage Company users' roles themselves.

**Security > Compliance** is different from the separate [Compliance assessment module](/user-guides/compliance/index). The Security tab reports provider events; the assessment module contains assigned checks, runs, guidance, and evidence.

## Company users: ask for investigation

Start with the [Home AI Assistant](/user-guides/ticketing/open-a-ticket). Describe the finding and include the company, affected resource, event type or CVE, provider, and displayed date. Review and confirm the support request when prompted. Viewing a finding does not create a ticket or remediate it.

## MSP staff: confirm setup and freshness

Check the active provider, imported company mapping, sync status, and user permissions. The Security reports display imported results; opening a tab or reloading a report is not a new provider scan.

Use the existing setup guides for [Cork](/user-guides/integrations/enable-cork-integration), [Acronis](/user-guides/integrations/enable-acronis-integration), [Huntress](/user-guides/integrations/enable-huntress-integration), [Phin](/user-guides/integrations/enable-phin-integration), or [CyberHoot](/user-guides/integrations/enable-cyberhoot-integration). For access changes, see [Company user permissions](/user-guides/settings/change-company-user-permissions).

## Frequently asked questions

<AccordionGroup>
  <Accordion title="Is Security only for Cork?">
    No. The provider table above shows which integrations supply each section. Permissions and active integrations control availability.
  </Accordion>
  <Accordion title="Why can I see Security Awareness but not the other tabs?">
    Security Awareness uses a separate read permission and supported awareness provider. Ask your MSP to confirm which access you need.
  </Accordion>
  <Accordion title="Is a Cork compliance event the same as an assessment check?">
    No. Use Security > Compliance for Cork events and the separate Compliance module for assessments.
  </Accordion>
  <Accordion title="Does an empty page prove there are no issues?">
    No. Scope, filters, missing mappings, stale data, or a loading problem can affect the result. Ask the MSP to verify the underlying provider data.
  </Accordion>
</AccordionGroup>
