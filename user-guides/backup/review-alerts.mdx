**Audience:** Company users and MSP staff with Backup read access and Acronis alert data in their permitted company scope.

## Review an alert

1. Open **Backup > Alerts**, or follow **View Alerts** from Dashboard when available.
2. Confirm the company selection.
3. Read **Severity**, **Title**, **Resource**, **Company**, **Status**, and **Created**.
4. Use pagination to inspect additional alert pages.
5. Report an unexpected or unresolved alert to the person responsible for the backup provider.

This table currently contains Acronis alerts. The Alerts tab appears only when eligible alert records are available; its absence does not establish that every connected provider is healthy.

The Title cell can show a shortened description. Created is the imported provider alert's creation time displayed relative to now. Status is the reported provider value. A resolved alert remains different from proof that the latest backup succeeded; check the underlying resource as well.

## Filter carefully

The table loads 25 alerts per server page. Its table filters operate on the currently loaded page. They do not search every alert on other pages. Use the main company selector to narrow the company scope, then inspect further pages as needed.

If the page shows **Failed to Load Alerts**, retry later or ask the MSP to check the integration. **No Backup Alerts** means there are no displayed records in the current result; it is not a health statement about Cove, NinjaOne, Kaseya, or Spanning.

## Company users: ask for investigation

Start with the [Home AI Assistant](/user-guides/ticketing/open-a-ticket). Include the alert title, provider, company, resource, severity, status, and creation time. Review and confirm the request when prompted. Reading an alert does not automatically create a ticket.

## MSP staff: follow up with the provider

Review the affected resource and imported activity. Use the authorized Acronis workflow for investigation and any changes. This table has no acknowledge, resolve, delete, or CSV-export control; changing the provider's alert is separate from viewing it in MSPortal.

## Frequently asked questions

<AccordionGroup>
  <Accordion title="Why can a search miss an alert on another page?">
    Table filters apply to the current loaded page. Use company scope and inspect the other pages before concluding an alert is absent.
  </Accordion>
  <Accordion title="Does Alerts include every backup provider?">
    The current table reads Acronis alerts. Review other providers through their available backup reports and provider workflows.
  </Accordion>
  <Accordion title="Can I resolve or acknowledge an alert here?">
    The Backup Alerts table is a reader. Authorized MSP staff perform those actions in the appropriate provider workflow.
  </Accordion>
  <Accordion title="Does Resolved prove my backups are current?">
    No. Review the latest relevant backup result and timestamp separately.
  </Accordion>
</AccordionGroup>
