**Audience:** MSP staff with Email settings access. Open **Settings > Email**. The three tabs are **Email Templates**, **Sending Domain** and **Receiving**. Each has its own save and action behavior.

## Edit notification templates

1. In **Email Templates**, preview the relevant template or open its editor. Create a new template when the existing category needs another option.
2. Review the category, name, subject, HTML content, plain-text content and supported variables. For an onboarding invitation, retain the required portal-link variable.
3. Save in the editor, wait for confirmation and reopen the saved template.
4. Review the default for its category before using a workflow that chooses the default automatically.

Creating and editing require Save. **Duplicate** creates a saved copy immediately; it does not merely open an unsaved draft. **Set as default** saves immediately for the template's category. Delete opens a confirmation. Previewing or saving a template is not a delivery test and does not itself send a message.

## Configure the sending domain

Open **Sending Domain**, add the intended domain, and copy its exact displayed DNS records to your DNS provider. Use **Check Verification** and inspect the returned status; pending is not verified. **Refresh Status** retrieves the current result. Save **Default From Address** with its separate control.

Follow [sending-domain setup](/user-guides/getting-started/onboarding/email-domain) for the sequence. Do not copy generic DNS examples. Domain removal has a confirmation and changes the organization's sender configuration; it does not remove DNS records at your provider.

## Manage receiving addresses

Opening Email settings can provision missing receiving addresses for existing companies. This is saved configuration even before you switch to the Receiving tab.

**Receiving** lists company-specific email import addresses with active/inactive status. Copy the address for the intended company, or use **Export CSV** to download the displayed address list. Treat the exported addresses as configuration information and share them only with the people setting up those imports.

Activation and deactivation save immediately. Regenerating one address or all addresses requires confirmation and changes the address used by incoming senders. Review the scope before confirming, then update any forwarding or report-delivery configuration that uses the old address.

**Regenerate All** can report updated, skipped and failed results. Inspect the refreshed list before retrying; a partial result does not mean every address remained unchanged. These addresses support [email imports](/user-guides/reporting/email-imports), not a general mailbox interface.

## Troubleshooting

| Problem | Check |
| --- | --- |
| A template preview looks correct but delivery failed | The sending workflow, recipient, sender verification and actual delivery result. |
| A sender still uses an old address | Confirm the saved From address and the workflow's selected template/sender settings. |
| An import stopped after regeneration | Update the source system to the new company address and check its active state. |
| A save or bulk action failed | Reopen the current values and inspect partial results before repeating it. |

## FAQs

<AccordionGroup>
  <Accordion title="Does duplicating an email template save it immediately?">
    Yes. Duplicate creates a saved copy; editing that copy is a separate save.
  </Accordion>
  <Accordion title="Does a preview send an email?">
    No. Preview and template saves are separate from actual sending and delivery verification.
  </Accordion>
  <Accordion title="Does the default apply to every category?">
    No. Default selection is scoped to the template category.
  </Accordion>
  <Accordion title="Do receiving address toggles need a header Save?">
    No. Activation and deactivation persist immediately.
  </Accordion>
  <Accordion title="What should I do after regenerating an address?">
    Copy the new company address and update the forwarding or report source that used the old one; inspect partial bulk results.
  </Accordion>
</AccordionGroup>
