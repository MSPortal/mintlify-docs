Use **Settings > Documentation > Liongard** to manage Liongard content on the **Documentation** page. This is an MSP configuration task requiring Documentation settings access and permission to save visibility rules. The Liongard tab depends on an active integration and imported content.

These rules grant access within the user's allowed tenant and company scope. They do not give a Company user access to other companies, configure compliance metric mappings, or change data in Liongard.

## Share an inspector type

The **Inspectors** section lists imported inspector types in use. Sharing a type grants access to its eligible systems, so inspect the scope before choosing a broad group.

<Steps>
  <Step title="Find the inspector">
    Use **Search inspectors...** to find the type in the table. Search changes the displayed rows; it does not limit the eventual save to those rows.
  </Step>
  <Step title="Choose permission groups">
    Use the row's group picker to add the Company permission groups that should have access. Select **All Permission Groups** explicitly (shown as an **All Groups** chip) when you intend unrestricted group matching within eligible company scope. Leaving the selection empty grants no access through that row.
  </Step>
  <Step title="Save the section">
    Review all pending edits in Inspectors, then click that section's **Save**. Group selections and chip removals are drafts until saved. Edits hidden by your search are included.
  </Step>
</Steps>

## Share an individual system

In **Individual Inspector Systems**, search by system name, select the correct result and verify its company. Adding a result to the editor alone does not share it: choose the required permission groups, then use this section's own **Save**.

An inspector-type rule and an individual-system rule are alternative grants. Removing an individual grant does not hide a system while an applicable type rule still grants access. To withdraw access, review both scopes, remove the relevant group selections and save the affected sections.

These sections do not offer a separate arbitrary company-target picker. A system's actual company and the viewer's allowed company scope still matter. **All Groups** does not mean all companies.

## Save and verify access

Saving one section does not save the other. Search does not discard hidden edits. If the page reports that another administrator changed the rules, refresh and reconcile the latest saved rules before retrying; do not assume your changes were applied.

For the Liongard Documentation listing, a qualifying inspector-type or system rule is required. MSP staff bypass the Company permission-group match for an existing rule; a staff preview is therefore not proof that a particular Company user can read the same item.

The general **Internal user access** selector above the tabs saves immediately when changed. Do not use it as a substitute for Liongard sharing rules or infer client access from its setting. Verify the Liongard listing and the intended Company account after saving rules.

Missing systems can also reflect company scope, ignored records, device import/type configuration, or incomplete synchronization. A visibility rule does not force every synced system into this listing.

## Troubleshoot missing content

First confirm the integration is active and the expected inspector/system is imported. Check the saved type and individual grants, the user's Company permission groups, and the system's company mapping. Reopen Documentation to check the result. If staff can see an item but a client cannot, investigate the client's permissions and group match rather than broadening every rule to All Groups.

## Frequently asked questions

<AccordionGroup>
  <Accordion title="Does leaving permission groups blank share the inspector with everyone?">
    No. An empty group selection creates no grant through that row. Select All Permission Groups explicitly when broad group matching is intended, then save the section.
  </Accordion>
  <Accordion title="Do group selections save immediately?">
    No. Inspector and individual-system rules are drafts until their section Save succeeds. The separate Internal user access selector does save immediately.
  </Accordion>
  <Accordion title="Does saving Inspectors also save Individual Inspector Systems?">
    No. Each section has its own Save. Review and save changes in both sections when the access change depends on both.
  </Accordion>
  <Accordion title="Does the search limit which edits Save applies?">
    No. Pending edits hidden by the current search remain included in the section save. Review the full set of changes before saving.
  </Accordion>
  <Accordion title="Why is a system still visible after I removed its individual rule?">
    An applicable inspector-type rule can still grant access. Review both type and system rules and the intended user before concluding that access was withdrawn.
  </Accordion>
  <Accordion title="Does All Groups expose data across companies?">
    No. It removes the group-match restriction for that grant within eligible company scope. It does not grant another company or tenant to a user.
  </Accordion>
  <Accordion title="Can my MSP preview prove a Company user can see the system?">
    No. MSP staff bypass the Company group match for an existing Liongard rule. Verify the intended Company user, group membership and allowed company scope separately.
  </Accordion>
  <Accordion title="Why is a synced system missing even though I saved a rule?">
    Check company mapping and scope, ignored status, device import/type configuration and sync state. Sharing rules do not force every synced system into the Liongard Documentation listing.
  </Accordion>
</AccordionGroup>
