Open **Cloud > Users** to review synchronized Microsoft 365 and Google Workspace accounts available to you. These are cloud-service identities; appearing here does not give someone an MSPortal login or a portal role.

**Audience:** Company users with Microsoft 365 read access and MSP staff. Your MSP manages access and account changes. Adobe-only license access does not include Cloud Users.

## Open and read an account

1. Open **Cloud**, then select the **Users** header tab.
2. Check the company selector in the top bar. If you can choose companies, narrow it to the company you are reviewing.
3. Find the account with the **Name** or **Email** column's **Filter...** field.
4. Check **Provider**, **Company**, and **Status** before interpreting the record. The page starts with **Status = Enabled**; [show disabled accounts](/user-guides/cloud/find-users) when needed.
5. Scroll the table horizontally to reach **2-step verification** and **Licenses** when they are off screen.

Rows are for reading. Cloud Users does not have an account-edit form, password-reset action, or license-assignment action.

## Understand the fields

| Field | What it shows |
| --- | --- |
| **Name / Email** | Synchronized display name and email. A missing display name can fall back to an email or sign-in name. |
| **Provider / Company** | The source service and mapped company. Provider is omitted for a single-provider scope; Company is omitted when the top bar is scoped to one company. |
| **Office** | Recorded location, or **No office** when absent. This does not establish whether someone works remotely. |
| **Department / Job title** | Directory attributes, available through **Columns**. Job title is a separate column. |
| **Status** | **Disabled** when the stored enabled flag is false; otherwise the display uses **Enabled**. |
| **Account type** | Member/Guest-style directory type where the current scope has more than one type. A recorded Google administrator flag can display **Administrator** in this column. |
| **2-step verification** | Recorded Google enrollment/enforcement flags; Microsoft rows show **Not available**. |
| **Licenses** | One friendly license name and **+N more** when there are additional names. Hover or keyboard-focus the license badges to read the full list. |
| **License count** | Number of distinct recorded SKU codes, available through **Columns**. |
| **Last login / Last synced** | Available sign-in and synchronization dates. Both can be shown through **Columns**. |

## Show additional columns

1. Click **Columns** above the table.
2. Select the columns you need. You can also drag their handles to change column order.
3. Click **Save Changes** to apply your column preferences. **Cancel** or closing the panel discards unsaved choices.
4. **Reset** restores the panel's default selections and order; click **Save Changes** to apply that reset.

## Interpret account and security information carefully

**Enabled** is a stored status, not proof of a successful sign-in today. **No licenses** means no license names are attached to this synchronized record; it does not prove that the person has no subscriptions, costs, or application access elsewhere. Check **Last synced** and ask your MSP to investigate discrepancies.

For Google, **Enforced** takes precedence when the stored enforcement flag is true. Otherwise a true enrollment flag shows **Enrolled**. **Not enrolled** is the fallback when neither flag is true, including when data is incomplete. Confirm the provider's current settings with your MSP before treating that label as a security finding.

For Microsoft, **Not available** in this column does not mean MFA is disabled. Use the appropriate [Cloud posture information](/user-guides/cloud/posture) and ask your MSP to check the provider settings.

**Account type** is not a complete administrator audit. Microsoft rows do not identify administrator roles here, Google admin labels can be absent when the whole column is omitted, and the type filter uses directory types rather than a dedicated Administrator filter. These values are separate from [MSPortal user permissions](/user-guides/settings/change-company-user-permissions).

## Request an account change

Company users should [open a ticket from the Home AI Assistant](/user-guides/ticketing/open-a-ticket) and include the company, provider, account, and requested change. Your MSP handles disabling accounts, assignment changes, and provider administration. A missing or disabled row alone does not confirm that every offboarding step is complete.

## FAQs

<AccordionGroup>
  <Accordion title="Does a Cloud Users row mean that person can sign in to MSPortal?">
    No. It represents a synchronized Microsoft or Google identity. MSPortal logins, roles, and company access are managed separately by your MSP.
  </Accordion>
  <Accordion title="Can a Company administrator disable users or reset passwords here?">
    No. Cloud Users is a reading page. Ask your MSP through a support ticket to make the account change.
  </Accordion>
  <Accordion title="Why does the same person appear more than once?">
    Records can represent separate provider accounts, sign-in identities, or company mappings. Compare Provider, Company, and Email before deciding that a record is a duplicate.
  </Accordion>
  <Accordion title="Does No licenses mean the account has no cost or access?">
    No. It means no license names are attached to this synchronized row. It does not measure billing, recent software use, or access through other accounts. Ask your MSP to check the underlying assignment data.
  </Accordion>
  <Accordion title="How can I see all the license names behind +N more?">
    Hover or keyboard-focus the license badge area. The tooltip lists all recorded names. The CSV also includes the full name list, and License count can be shown through Columns.
  </Accordion>
  <Accordion title="Does Not available mean Microsoft MFA is turned off?">
    No. This per-user column does not report Microsoft MFA state. Review the relevant posture information and have your MSP confirm current settings.
  </Accordion>
  <Accordion title="Does Google's Not enrolled label prove that 2-step verification is absent?">
    Not by itself. The label is used when neither stored flag is true, which can include incomplete data. Check synchronization and ask your MSP to confirm the provider state.
  </Accordion>
  <Accordion title="Can I use Account type to list every administrator?">
    No. It is primarily a directory Member/Guest-type field. It does not enumerate Microsoft administrator roles and may be omitted for a single-type scope, including Google-only scopes. Your MSP should verify administrator roles in the relevant provider.
  </Accordion>
</AccordionGroup>
